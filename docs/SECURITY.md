# Защита и ограничения

## Данные на диске

SQLite содержит одну запись с версионированным зашифрованным снимком. Внутри снимка:
ассоциации, названия, поля, имена/типы файлов, содержимое файлов в base64 и настройки.
Пароли не хешируются как самостоятельная запись: правильность мастер-пароля проверяется
по успешному аутентифицированному расшифрованию. Используются AES-256-GCM, ключ 256 бит,
PBKDF2-SHA256 (600 000 итераций), salt 32 байта, nonce 12 байт и тег 16 байт.
Каждая запись получает новый nonce. Смена пароля создаёт новый salt и ключ и записывается
транзакционно. Неверный старый пароль не меняет данные.

Дисковая SQLite и журнал транзакций содержат только шифротекст. FTS5/unicode61 индексирует
названия в отдельной in-memory SQLite, которая закрывается при блокировке. Значения полей
не индексируются. Поиск сопоставляет любое из введённых слов по префиксам; синтаксис FTS
не принимается напрямую, пользовательские токены передаются параметром SQL.

## Экспорт и импорт

`.smvault` — версионированный JSON-конверт с зашифрованным payload и SHA-256 этого payload.
Сначала проверяется SHA-256, затем обязательный тег AES-GCM, затем схема и ограничения.
Контрольная сумма не является доказательством подлинности: злоумышленник может её
пересчитать. Подмену при этом всё равно обнаруживает AES-GCM. Экспорт и локальное
хранилище используют разные associated-data contexts и независимые salts/ключи.

До завершения проверки и выбора действий для всех конфликтов импорт ничего не меняет.
Идентификатор либо совпавшее без учёта регистра название вызывают разрешение конфликта.
Одинаковая копия повторно не дублируется. Импорт не отключает настройки локальной защиты.

## Сессия и буфер

При блокировке интерфейс и поиск очищаются, индекс закрывается, массив ключа затирается.
Открытые диалоги скрываются; асинхронные действия проверяют, что сессия не сменилась.
Блокировка Windows также закрывает хранилище. Второй экземпляр запрещён, чтобы два
независимых снимка не перезаписывали изменения друг друга.

Текстовые строки и объекты .NET невозможно гарантированно стереть из памяти; GC,
swap, crash dumps и привилегированный процесс могут сохранить расшифрованные данные.
Это приложение не защищает от вредоносной программы на разблокированном компьютере,
кейлоггера, захвата экрана или администратора. Слабый пароль уязвим к перебору офлайн.

Буфер запрещён для Windows Clipboard History/roaming. Очистка с таймером проверяет
маркер владельца: новые данные другой программы не стираются. Копирование обычного
файла требует временного открытого файла в `%LocalAppData%\SecretManager\Clipboard`.
Он удаляется при очистке/блокировке/следующем запуске после сбоя; удаление не является
гарантированным физическим стиранием с носителя. Другая программа может прочитать
буфер до истечения таймера. Изображения передаются в буфер через поток в памяти.

## Ограничения версии

Диагностика хранится локально в `Logs`: время, версия, имена операций и методов,
типы/HRESULT исключений. Сообщения исключений, Data, пути из stack trace, названия
ассоциаций, описания, значения, пароли и метаданные вложений не сериализуются.
Дампы памяти приложение не создаёт. Файл ротируется при 256 КБ, сохраняется одна
предыдущая копия. Для аварий WinUI, не дошедших до .NET, сохраняется маркер
незавершённого сеанса; подробности самого нативного сбоя могут быть только в Windows.

- Windows x64, Windows 10 2004 / 19041 или новее.
- Вложение до 10 МБ, сериализованный снимок до 64 МБ, предпросмотр PNG/JPEG до 40 Мп.
- Полный снимок переписывается при изменениях: это приложение для личного объёма данных.
- Синхронизация ручная через экспорт/импорт, сервера и почтового входа нет.
- Мастер-пароль не восстанавливается. Не удаляйте единственную резервную копию.
- Код и установщик первой версии не проходили независимый аудит; подпись установщика
  требует отдельного сертификата издателя. SmartScreen может показывать предупреждение.
- Удаление приложения сохраняет пользовательскую БД. Бинарники и секретные данные
  не включаются в Git; в релизе хранится только актуальный установщик.
