# Проверка интерфейса

Автоматические тесты ядра и ViewModel не заменяют проверку Windows-интеграции.
Во время первичной разработки инструмент Computer Use отклонил доступ к окну
SecretManager даже после явного разрешения пользователя. Ниже сценарии для
интерактивной проверки; они не отмечены выполненными автоматически.

Используйте вымышленные данные и отдельную базу. Для диагностического запуска можно
задать `SECRETMANAGER_DATA_DIR` в каталог вне настоящего хранилища.

- [ ] Создать мастер-пароль, закрыть/открыть, проверить неверный и верный пароль.
- [ ] Добавить две темы, по нескольку текстовых/секретных полей, PNG/JPEG и произвольный файл.
- [ ] Проверить раскрытие, сворачивание, переход из меню и поиск кириллицей в другом регистре.
- [ ] Проверить изменение описания/значения/названия и удаление поля/ассоциации.
- [ ] Скопировать текст и файл; изображение должно копироваться и открываться крупно.
- [ ] Подождать очистки буфера; скопировать другой текст извне и убедиться, что он не удалён.
- [ ] Экспортировать, импортировать на новом профиле, проверить все три варианта конфликта.
- [ ] Изменить файл экспорта: импорт должен остановиться до записи в БД.
- [ ] Проверить темы, ColorPicker, типографику, предпросмотр, отмену и сохранение настроек.
- [ ] Проверить три уровня движения, скорость, системное отключение анимаций.
- [ ] Проверить Ctrl+L, Ctrl+F, блокировку Windows и пять минут без фокуса.
- [ ] Крестик в трей, левый клик для открытия, статус/цвет значка, контекстное меню и выход.
- [ ] Отключить уход в трей: крестик должен завершать процесс.
- [ ] Проверить FAQ, клавиатурную навигацию, масштаб Windows 125/150/200% и узкое окно.

Проверка установки/удаления и запуск процесса проверяются отдельно командами,
без имитации интерактивного UI-прогона. Фактические результаты — в WORK_LOG.md.
