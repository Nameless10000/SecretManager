Дата начала: 26.10.2026.

## Согласовано

- Имя приложения и публичного репозитория: SecretManager.
- .NET 10, WinUI 3 + MVVM, SQLite, Windows x64.
- Почтовый вход исключён. Локальное хранилище открывает мастер-пароль.
- Импорт объединяет данные, при конфликте пользователь выбирает действие.

## Решения

- SQLite содержит зашифрованный JSON-снимок. Вложения кодируются base64 внутри
  снимка и затем шифруются вместе с текстами и названиями.
- AES-256-GCM, PBKDF2-SHA256 (600 000 итераций), отдельные salt/nonce; проверка
  целостности до десериализации. Экспорт с отдельным паролем и контекстом шифрования.
- Индекс названий FTS5 / unicode61 строится в памяти после входа; значения не индексируются.
- Закрытие в трей по умолчанию блокирует хранилище сразу. Явный выход есть в меню трея.
- Автоблокировка отсчитывает отсутствие фокуса, включая свёрнутое/скрытое окно.
- Автоочистка буфера через 30 секунд удаляет только данные, скопированные приложением.
- Дополнено: темы Light/Dark/Midnight/Forest/Custom, редактор цветов и типографики,
  плотность и скругления, анимации Off/Medium/Maximum и скорость.
- Установщик: один актуальный SecretManager-Setup.exe, один GitHub release latest.
- NuGet-аудит выявил уязвимый SQLitePCLRaw.lib.e_sqlite3 2.1.11; использован
  Microsoft.Data.Sqlite.Core + SQLitePCLRaw.bundle_e_sqlite3 3.0.5, предупреждение устранено.
- VSTest в песочнице не смог подключиться к testhost; повторный обычный запуск
  вне песочницы прошёл: 22/22, без пропусков (26.10.2026).
- Публичный репозиторий создан, первый коммит отправлен: https://github.com/Nameless10000/SecretManager.

## Исправления 0.1.1 по обратной связи

### Оформление и анимации — реализовано, проверено

- Устранено смешивание цветов после переключения тем в обе стороны. ThemeResources
  создаётся до дочерних контролов и сохраняет экземпляры кистей; меняется Color,
  а не запись словаря. Это исправляет также переходы Dark/Midnight/Forest без смены
  базового ElementTheme и возврат к System.
- Общая палитра применена к меню, настройкам, карточкам, нативным кнопкам/полям,
  акцентам, диалогам и кнопкам заголовка окна. Текст контрастирует с поверхностями;
  вторичные подписи используют цвет, а не низкую opacity.
- Смена типографики не затрагивает IconElement и символьные шрифты внутренних
  TextBlock. Исправляет квадратики вместо значков WinUI.
- Для увеличения карточки добавлен горизонтальный отступ 12 px. Рост ограничен
  6 px с каждой стороны, с запасом на пружинный выброс, включая широкие окна.
- Строка действий снизу слева удалена. Уведомление заменено компактным overlay:
  оно не занимает отдельную строку Grid, не сдвигает список и исчезает через 2 с.
- 53 теста ядра, ViewModel, контраста и геометрии прошли.
- Новый изолированный WinUI-стенд использует настоящие ThemeResources, ThemeService
  и ToastNotification приложения, синтетические поля и не открывает пользовательскую БД.
  Проверены 64 перехода между 8 вариантами палитры, включая возврат в System,
  нативные accent-кнопки, стабильность ссылок кистей, символьные шрифты, запас hover,
  положение/размер списка до и после toast, его исчезновение и очистка сообщения.
- RenderTargetBitmap сохранил 9 PNG в artifacts/theme-checks. Все просмотрены:
  Light, Dark, Midnight, Forest, Custom Light/Dark/Gray, текущая System и toast.
  Это проверки WinUI-стенда; ручной прогон пользовательского окна не заявляется.

## Изменения 0.1.2

- Блокировка: воспроизведён сбой обеих точек входа — LockCommand и Lock из Ctrl+L.
  Синхронный обработчик CollectionChanged читает CountLabel, пока IsUnlocked ещё true,
  хотя session.Document уже недоступен. Оба регрессионных теста упали с тем же
  InvalidOperationException до исправления. Состояние locked теперь устанавливается
  до уведомлений коллекции/свойств. Тесты также проверяют повторный вход и сохранность полей.
- Блокировка исправлена: оба исходно падавших регрессионных теста теперь проходят;
  проверены повторная блокировка и сохранность записей после повторного входа.
- Входящие вложения читаются с лимитом фактически прочитанных байтов, без доверия
  к предварительному размеру файла. Файлы/PNG/JPEG принимаются через общую зону
  перетаскивания и существующий file picker. Одно поле принимает один файл.
- Картинки из DataPackage Bitmap (включая BMP) преобразуются в PNG в памяти;
  поддержан скопированный PNG/JPEG-файл. Кнопка и Ctrl+V в редакторе, кроме
  текстовых полей. Картинка показывается в уменьшенном предпросмотре без искажения пропорций.
- Неверный формат, папка, несколько файлов, повреждённый PNG и превышение лимита
  не заменяют выбранное вложение. Закрытие редактора/блокировка инвалидируют
  результат отложенного провайдера. Пользовательский системный буфер в тестах
  не читался и не менялся: использованы синтетические DataPackage/GetView.
- Обработчики UI теперь явно обрабатывают InvalidDataException: эта ошибка
  проверки не должна приводить к завершению процесса. Очистка буфера допускает
  временную недоступность буфера/экрана блокировки Windows.
- Добавлена сохранённая настройка SingleExpandedAssociation, по умолчанию true.
  Связанные карточки сворачиваются при открытии другой; при отключении доступны
  несколько раскрытых карточек. Включение настройки сохраняет последнюю открытую.
- По ролику (6.07 с, просмотрены кадры; копии только в ignored artifacts)
  подтверждена резкая смена фона burger-кнопки. BackgroundTransition настроен
  для нативных ContentPresenter/Border/Panel всех кнопок, в том числе замка и
  настроек: 120/180 мс с учётом скорости, отключается вместе с анимациями.
- 63 теста Core/ViewModel прошли. WinUI-стенд: 64 перехода тем, toast, переходы
  фона и 11 сценариев вложений (binary, PNG, JPEG, смена типа, multi/folder,
  повреждение, URL, размер, bitmap -> PNG и поздний результат после закрытия).
- Версия приложения/установщика 0.1.2. Финальная упаковка и публикация — в работе.
- CI после успешных 63/64/11 проверок падает на завершении WinUI: первоначально
  C0000005, после очистки фокуса — C000027B уже после Window.Close. Локально
  процесс завершается с кодом 0, в том числе с runtime .NET 10.0.14 как в CI.
  Перенос Close в очередь проблему CI не решил. Добавлен наблюдатель stowed
  exception только в синтетический стенд: HRESULT и адреса стеков в журнал,
  без подавления исключения, дампов памяти и изменения условий успеха.
- Повторная сборка отдельным SDK 10.0.403 также проходит локально с кодом 0.
  Vectored observer не вызывается при fatal shutdown в CI. При сбое CI теперь
  повторно запускает синтетический стенд под ProcDump и разбирает дамп CDB;
  дампы не публикуются, исходный ненулевой exit code по-прежнему блокирует релиз.
